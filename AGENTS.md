# AGENTS.md — `.opencode/` harness spec

This repo is the `.opencode/` engineering harness itself: shell toolchain (`tools/`), rules (`rules/`), agents (`agents/`), commands (`commands/`), skills (`skills/`). No build manifest; no test suite; no CI (`.github/` absent). Source: 10 shell files, ~1133 LOC (`digest.sh`). Quality gate: `.opencode/tools/quality.sh` (strictest flags; skips = uncovered surface, not green — `rules/quality-bar.md`). Every claim needs a command + output; UNKNOWN = FAIL (`rules/prompt-contract.md`).

## 2. Code style & architectural invariants

- **Shell**: POSIX `#!/bin/sh` preferred; `#!/bin/bash` only if bash-only (`refactor-shell.md`). Quote every expansion (`"$var"`). `set -euo pipefail`. Max 25 lines/function. `printf` over `echo`. `command -v` over `which`. `local` variables; `trap` cleanup (`refactor-shell.md`).
- **Library-first**: Every tool is thin glue over `tools/lib/common.sh`. Before writing feature code, search `rg` + `codemap.sh`. Extract before second copy (`library-first.md`).
- **No dead code**: No commented-out code. No `TODO` without linked issue (`refactor-common.md`).
- **Naming**: Behavior, not implementation. Consistent vocabulary (`fetch/get/retrieve` — pick one). No single-letter names outside loops/math (`refactor-common.md`).
- **Errors**: Every fallible operation handled explicitly. Messages include: what failed, why, caller action. No silent swallows (`refactor-common.md`).
- **Memory/resources**: Every allocation has an owner and free path. No leaks (FD, goroutine, subscription) (`refactor-common.md`).
- **Dependencies**: Prefer stdlib. If a dependency is used for one function, inline it (`library-first.md`).
- **Minimalism ladder** (`minimalism-ladder.md`): YAGNI → stdlib → platform → existing dep → one-liner → minimum. Hot-path override requires a measured number (`benchmarker.md`), not an adjective.
- **Data structures** (`dsa-and-memory.md`): Name access pattern first; structure follows. No O(n²) on unbounded input. Pre-size slices (`make([]T, 0, n)`). Pool high-churn allocations (`sync.Pool` in Go; arenas in C; reuse buffers in TS).

## 3. Agent boundaries & forbidden actions

- **FORBIDDEN**: Never edit `node_modules/`, `.git/`, or generated artifacts directly.
- **FORBIDDEN**: Never modify lockfiles (`package-lock.json`) by hand; use package manager CLI.
- **FORBIDDEN**: Never run destructive git ops (`reset --hard`, `clean -fd`, `push --force`) without explicit human trigger (`run-safely.md`).
- **FORBIDDEN**: Never bypass verification gates (`git commit --no-verify`, lint suppressions without linked issue — `quality-bar.md`).
- **FORBIDDEN**: Never hardcode secrets, mock credentials, or API keys in code or commits.
- **FORBIDDEN**: Never claim a pass without the command + output that proves it (`prompt-contract.md`).
- **FORBIDDEN**: Never leave a half-state. Green gate or revert to last green — no red bars left (`builder.md`).
- **FORBIDDEN**: Never co-author (`Co-Authored-By`, "Generated with").
- **FORBIDDEN**: Never mix refactor and feature in one commit (`refactor-common.md`).
- **FORBIDDEN**: Never run unbounded commands without `.opencode/tools/watch.sh` (`run-safely.md`).

## 4. Execution & verification lifecycle

Every agent modifying this codebase MUST complete this loop before declaring done:

1. **Brief**: `.opencode/tools/digest.sh` (cached; `--refresh` after changes).
2. **Preflight**: `.opencode/tools/preflight.sh`. Unset required var = blocker, not warning.
3. **Contract**: Restate task as inputs → outputs → exact done-when. Vague? Sharpen (`/prompt`) (`prompt-contract.md`).
4. **Library check**: `rg` / `.opencode/tools/codemap.sh` / `.opencode/tools/dupes.sh`. Reuse before write (`library-first.md`).
5. **TDD**: Write failing test first (`rules/test-frameworks.md`). RED → GREEN (minimum code) → REFACTOR (`refactor-<tech>.md`).
6. **Smallest check**: Run targeted test after each change.
7. **Gate**: `.opencode/tools/quality.sh --with-tests`. Every relevant gate green at strictest flags. Name skips (`quality-bar.md`).
8. **Scope audit**: `git status -s`. No leftover artifacts, unintentional mutations, untracked temp files.
9. **Report**: Command + output for every claim. Failures stated; skips stated. No adjectives without numbers (`prompt-contract.md`).

## 5. Multiagent workflow

This is a **standalone** harness with **no orchestrator kernel**. Keep multi-agent work lean and disposable: fan out for independent slices, converge on one gate, discard scaffolding. Do not build half a kernel.

- **Fan out** only for genuinely independent slices (separate files, separate modules, separate review dimensions). No shared write target.
- **Sequence** dependency chains (migrate → verify). Parallelizing corrupts state.
- **Right-size**: Trivial/conversational tasks need zero subagents. Reserve fan-out for breadth (many files) or confidence (independent perspectives before irreversible step).
- **Every subagent gets**: one job + one verifiable done-when; the context it needs + binding rules (§3); a structured output schema; read-by-query discipline (`rg`/`jq`/`awk`, not dumps).
- **Cross-check claims**: UNKNOWN = FAIL. A finding without evidence (`file:line` or command + output) is a hypothesis.
- **Re-verify state** before any destructive/irreversible step. Confirm target now, not from a stale scan.
- **Adversarial pass** for high-stakes findings: spawn skeptics to refute; default to refuted when uncertain. For irreversible/high-blast plans, get `devil` verdict first (`/workflow:deal`, `rules/risk.md`).
- **Converge on one gate**: tester + `reviewer`, or `.opencode/tools/quality.sh`. A gate that passes vacuously is not a gate.
- **Measured, not claimed**: Every perf/capacity statement cites artifact + reproduction command. No invented numbers (`benchmarker.md`).

### 5.1 Non-negotiables (binding for every subagent)

- Use the project's toolchain (`facts.sh`); run under `watch.sh`.
- Backward-compatible by default — new behavior additive/opt-in until proven.
- Backend-agnostic — a fix for one adapter that breaks another is not done.
- Confirm irreversible actions (push, deploy, delete, migrate, security cutover) → explicit human trigger.
- Stage risky changes — verify new path against old before deleting old; UNKNOWN = FAIL.
- Verify before run (`preflight`); quality gate green before "done".
- Report faithfully — failures stated, skips stated; clean result only when verified.

### 5.2 Agent roster

Pick the narrowest agent; compose at a gate (§5). Read `.opencode/agents/<name>.md` before dispatching.

| Agent | Role | Key constraint |
|---|---|---|
| `builder` | TDD, library-first, fact-driven; ships with every gate green | No half-states; green or revert (`builder.md`) |
| `forger` | Toolsmith; makes rules self-enforcing; iterates on feedback | Extract before duplicate (`library-first.md`) |
| `innovator` | 10x ideas grounded in facts; each with cheap experiment + kill criterion | No unmeasured claims (`benchmarker.md`) |
| `architect` | Boundaries, contracts, data flow; produces decisions/interfaces, not code | No infrastructure types in domain signatures (`refactor-go.md`) |
| `devil` | Risk magistrate; BLOCK / PROCEED-WITH-CONDITIONS / PROCEED before risky code | UNKNOWN = BLOCK (`risk.md`) |
| `documenter` | Docs only; never touches source; examples from tests | No invented examples (`documenter.md`) |
| `reviewer` | Strict merge review: correctness, leaks, contract violations, bloat | Zero suppressions without linked issue (`quality-bar.md`) |
| `security` | White-box attacker; finds exploit, rates it, names minimal fix | Read-only; never writes fix (`security.md`) |
| `benchmarker` | Performance in numbers against baseline; no adjectives | Cite artifact + reproduction command (`benchmarker.md`) |
| `compat-tester` | Measured behavioral parity vs reference; endpoint by endpoint | Additive/opt-in until proven (`compat-tester.md`) |
| `norminette` | 42 C-norm enforcer; opt-in for C/42 projects; real CLI | PASS/FAIL only (`norminette.md`) |

Agents without project files (`explore`, `general`) are runtime/built-in — verify behavior before use; do not claim a project spec for them.
